# Cheatsheet: Quick Reference & Decision Tables

## Quick Start: 5-Minute Pyramid

**Step 1: Identify your point**
- What is your main conclusion/recommendation?
- Can you say it in one sentence?

**Step 2: Find 2-4 supporting reasons**
- Why is your point correct?
- What makes it urgent/important/feasible?

**Step 3: Add evidence**
- What proof supports each reason?
- What would make a skeptic believe you?

**Step 4: Write SCQA preamble**
- Situation: What context does reader know?
- Complication: What changed?
- Question: What problem does that create?
- Answer: Your main point

**Step 5: Structure it**
```
[SCQA Preamble]
|
Your Main Point
├─ Reason 1 → Evidence
├─ Reason 2 → Evidence
└─ Reason 3 → Evidence
```

## Decision Table 1: Grouping Method

**Question**: How should I organize these 3+ ideas at this level?

| I Have | Use This | Looks Like |
|--------|----------|-----------|
| Ideas that follow logically (If A, then B, then C) | **Deductive** | Syllogism: Premise → Premise → Conclusion |
| Multiple examples of same pattern | **Inductive** | Examples → Summary generalization |
| Ideas ordered by time | **Chronological** | First → Next → Finally |
| Ideas organized by location/structure | **Structural** | Top → Middle → Bottom |
| Ideas from most to least important | **Degree** | High importance → Medium → Low |

## Decision Table 2: When to Use Each Pyramid Type

| Situation | Use This Pyramid | Example |
|-----------|-----------------|---------|
| Making a recommendation | **Recommendation** | "We should enter the Asian market" |
| Explaining what happened | **Narrative Analysis** | "Sales declined because competition intensified" |
| Analyzing a situation | **Diagnostic** | "The problem is X, not Y" |
| Presenting findings | **Analytical** | "Three factors drive success in this industry" |
| Building an argument | **Argumentative** | "Product A is superior because of B, C, D" |

## Decision Table 3: Horizontal Relationship Tests

**Does each supporting idea at this level pass all tests?**

| Test | Question | Pass Means |
|------|----------|-----------|
| **Mutual Exclusivity** | Do these ideas overlap or contradict? | Each idea is separate; no idea fits in multiple categories |
| **Collective Exhaustiveness** | Do these ideas cover everything needed to prove the point? | Nothing important is missing; reader won't say "but what about X?" |
| **Logical Similarity** | Are these grouped by the same principle? | All are reasons, all are problems, all are benefits (not mixed) |

**Fail = You need to regroup**

---

## Decision Table 4: The 3:1 Rule

**Question**: Do all my supporting ideas deserve to be at the same level?

| Situation | Action |
|-----------|--------|
| One idea is clearly 3+ times stronger than others | **Promote it to main point**, demote weaker ones |
| All ideas are roughly equal in strength | **Keep as peers** at same level |
| Ideas are mixed strength | **Regroup**: Strong ones become main point, weak ones become reasons for one strong idea |

## Decision Table 6: Ordering Principles

**How should I sequence my supporting ideas?**

| Order Type | Use When | Example |
|-----------|----------|---------|
| **Deductive** | One reason logically follows from another | Premise 1 → Premise 2 → Conclusion |
| **Inductive Theme** | All reasons share theme | Problem 1, Problem 2, Problem 3 → Common theme |
| **Chronological** | Timeline/sequence matters | First this, then that, finally this |
| **Structural** | Spatial/org structure matters | Region 1, Region 2, Region 3 |
| **Importance** | Priority or magnitude matters | Biggest impact first, then medium, then small |
| **Audience Interest** | What captures attention first | Start with what they care most about |

## Decision Table 7: Problem Definition Framework (Ch8)

**Use this to structure any problem statement**:

| Element | What It Is | Example |
|---------|-----------|---------|
| **Background** | Current stable situation/context | "We've used 3 warehouses for 5 years" |
| **Complication** | Event/change that disrupted normal | "Demand up 15%, new 200 stores opening" |
| **R1 (Current)** | Undesired result from complication | "Warehouse capacity now 150% utilized" |
| **R2 (Desired)** | Target outcome you want | "Maintain 80% utilization for flexibility" |
| **Problem** | Gap between R1 and R2 | "Need additional 40% capacity in 18 months" |

## Decision Table 8: Diagnostic Framework Method (Ch9)

**Which analysis method should I use?**

| Problem Type | Method | Steps |
|-------------|--------|-------|
| **System not working** | Structure analysis | Draw current system → Identify failure points → Test hypotheses |
| **Metrics declining** | Causal analysis | Break metric into components (e.g., Profit=Revenue-Cost) → Test each |
| **Multiple causes possible** | Classification | Group potential causes by type using MECE → Test systematically |
| **Complex decision needed** | Logic tree | Break question into sub-questions → Create hierarchy → Evaluate options |

## Diagnostic Decision Tree (Updated - Ch8, Ch9)

**Use this when analyzing a problem**:

```
START: "What is the problem?"
    ↓
DEFINE PROBLEM (Ch8): Background-Complication-R1-R2
    ↓
"Is it a diagnostic problem (why?) or evaluative problem (which one)?"
    ↓
DIAGNOSTIC (Ch9):
├─ Choose method: Structure | Causal | Classification
├─ Build diagnostic framework
├─ Generate hypotheses
├─ Test each hypothesis
├─ Identify root causes
└─ Design solution
    
EVALUATIVE:
├─ Define decision criteria
├─ Build logic tree of options
├─ Evaluate each against criteria
├─ Select best option
└─ Plan implementation
```

## Decision Table 9: Formatting Method (Ch10)

**Which formatting method should I use?**

| Document Type | Best Method | Why |
|--------------|-------------|-----|
| Long report/proposal | Multi-level headings | Reveals structure, enables scanning, serves as table of contents |
| Medium document (3-5 pages) | Underlining key points | Highlights supporting ideas without breaking flow |
| Policy/specification | Numerical indexing | Enables precise references (see Section 1.2.3) |
| Short memo/email | Line indentation | Minimal formatting, maintains informal tone |
| Executive brief | Bullet points | Scannable, emphasizes key conclusions |

## Decision Table 10: Slide Design (Ch11)

**How should I structure a presentation?**

| Slide Type | Content | Example Title |
|-----------|---------|----------------|
| **Thesis** | Your recommendation (1 slide) | "Implement preventive maintenance program" |
| **Supporting Reason** | One supporting argument (1 slide each) | "Maintenance will restore 50% of lost production" |
| **Evidence** | Data proving reason (1+ slides per reason) | [Chart showing downtime trends] |
| **Transition** | Summary of section + preview next (optional) | "We've covered three solutions; now let's review ROI" |
| **Conclusion** | Restate thesis + next steps | "Launch pilot in Q3, full rollout if successful" |

**Rule**: One idea per slide. If your slide has multiple messages, split it.

## Decision Table 11: Heading Rules (Ch10)

**Does your heading pass the Six Rules test?**

| Rule | Check | Fix |
|------|-------|-----|
| **Not alone** | Do I have 2+ headings at this level? | Create groups of headings; no single headings |
| **Parallel structure** | Do all headings at this level use same grammar? | Rewrite so all start with verbs or all with nouns |
| **Conveys idea** | Does heading express core idea without full sentence? | Remove generic words; add specific nouns/verbs |
| **Separate from body** | Does body restate heading? | Make first sentence after heading new thought |
| **Introduced** | Did I explain what this section covers? | Add intro paragraph after major heading |
| **Not overused** | Do I have too many heading levels? | Limit to 3-4 hierarchy levels max |

## Anti-Pattern Checklist

**Before you present, check for these mistakes**:

- [ ] Do I bury my main point? (Fix: Move to top)
- [ ] Are my supporting ideas clearly connected? (Fix: Add logical link words)
- [ ] Do all ideas at one level share a grouping principle? (Fix: Regroup by theme)
- [ ] Do I have 5+ ideas at one level? (Fix: Create sub-groups)
- [ ] Does my preamble raise the right question? (Fix: Check SCQA flow)
- [ ] Do I provide evidence before raising the question? (Fix: Reorder)
- [ ] Are some supporting ideas much weaker than others? (Fix: Promote strong one to main point)

## One-Minute Pyramid Test

**Can you pass this test? If not, your pyramid isn't clear**:

1. **State your main point in one sentence** → If you can't, it's not clear enough
2. **Why are your 2-3 reasons valid?** → If reasons don't support point, restructure
3. **Would a smart skeptic believe you?** → If not, add more evidence or change reasons
4. **Could someone read only the main points** (top + middle level) **and understand?** → If not, your support isn't aligned

## Templates to Copy

### Email to Busy Executive
```
Subject: [One-sentence main point]

[SCQA preamble: 2 sentences]

Bottom line: [Your recommendation]

Key reasons:
1. [Reason 1]
2. [Reason 2]
3. [Reason 3]

More details: [Link to full report]
```

### 1-Page Executive Summary
```
[SCQA preamble: 1 paragraph]

RECOMMENDATION: [Main point: one sentence]

SUPPORTING REASONS:
1. [Reason 1 with 1-2 sentences of detail]
2. [Reason 2 with 1-2 sentences of detail]
3. [Reason 3 with 1-2 sentences of detail]

FINANCIAL IMPACT: [In dollars/percentage]

NEXT STEPS:
1. [Action]
2. [Action]
3. [Action]
```
