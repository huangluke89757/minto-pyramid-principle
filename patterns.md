# Patterns: Frameworks & Techniques

## Core Framework Patterns

### Pattern 1: The SCQA Preamble (Situation-Complication-Question-Answer)

**Structure**:
```
Situation: [Context reader knows]
    → Complication: [New development that changes things]
        → Question: [Problem this creates]
            → Answer: [Your main point]
```

**Example**:
- **S**: "Our market has been stable for 5 years with 3 major players"
- **C**: "A well-funded startup with innovative technology entered our space"
- **Q**: "How do we respond to this competitive threat?"
- **A**: "We should focus on vertical integration rather than price competition"

**When to use**: Every written report, email to leadership, or formal presentation opening

### Pattern 2: The Pyramid of Recommendation

**Structure**:
```
Top: "We should do X"
├─ Support 1: "Because reason A is compelling"
├─ Support 2: "Because reason B is urgent"
└─ Support 3: "Because reason C is feasible"
    ├─ Evidence for A
    ├─ Evidence for B
    └─ Evidence for C
```

**Use when**: Making a business decision, recommendation, or proposal

### Pattern 3: The Problem Definition Framework (Ch8)

**Structure**:
```
Background (current stable state/context)
    ↓
Complication (event or change that disrupts)
    ↓
R1 (Undesired result - current problem)
    ↓
R2 (Desired result - target state)
    ↓
Problem = Gap between R1 and R2
```

**Use when**: Formally defining any problem before attempting to solve it

### Pattern 3B: The Diagnostic Framework (Ch9)

**Structure**:
```
Problem statement
├─ Possible cause 1 (from structure analysis) → Test → Confirmed/Rejected
├─ Possible cause 2 (from causal analysis) → Test → Confirmed/Rejected
└─ Possible cause 3 (from classification) → Test → Confirmed/Rejected
```

**Three construction methods**:
1. **Structure method**: Draw system/process, identify failure points
2. **Causal method**: Create financial/task/action structures showing cause-effect
3. **Classification method**: Group causes by type, use MECE principle

**Use when**: Investigating root causes, troubleshooting, or problem analysis

### Pattern 4: The Logic Tree (Issue Tree)

**Definition**: Hierarchical breakdown of a complex question into simpler sub-questions

**Example structure**:
```
"How can we improve profitability?"
├─ Increase revenue
│  ├─ Expand customer base
│  ├─ Increase price
│  └─ Expand product line
└─ Reduce costs
   ├─ Labor efficiency
   ├─ Supplier negotiation
   └─ Process automation
```

**Use when**: Analyzing complex problems, conducting structured consulting-style analysis

## Communication Techniques

### Technique 1: Vertical Emphasis (Question-Answer Dialogue)

**How it works**:
- Each statement raises an implicit question
- The next level down answers it
- Reader is pulled through the logic

**Example**:
- Statement: "Our retention rate is declining" (reader thinks: "Why?")
- Answer: "Churn increased 15% among enterprise customers" (reader thinks: "Why them?")
- Detail: "They report lack of X feature competitors provide"

### Technique 2: Horizontal Grouping

**Three grouping types**:

1. **Deductive grouping** (one conclusion from premises):
   - Premise 1 + Premise 2 → Conclusion
   - The conclusion is the single supporting idea

2. **Inductive grouping** (multiple similar ideas):
   - Reason 1, Reason 2, Reason 3 → Common theme
   - Summarize theme above the reasons

3. **Narrative grouping** (story order):
   - First, then, finally (chronological)
   - Use when sequence matters

### Technique 3: The Inversion Test

**Purpose**: Verify your horizontal logic is truly parallel

**Method**:
- State your supporting ideas
- Flip to opposites: "If this is true, then that should be false"
- If opposite ideas are still consistent, grouping is wrong

**Example**:
- Ideas: "Sales team is experienced, Marketing team is innovative, Finance team is data-driven"
- Problem: These don't connect; could add any attribute
- Better grouping: "Sales team drives revenue, Marketing team drives brand, Finance team controls costs"

### Technique 4: Formatting for Visual Clarity (Ch10)

**Six Formatting Rules**:
1. Never have only one heading at any level
2. Use parallel structure (all verbs or all nouns at same level)
3. Make heading words convey core idea
4. Separate heading from body text
5. Introduce each set of headings
6. Don't overuse headings (reserve for structure)

**Five formatting methods**:
- Multi-level headings (recommended)
- Underlining key points
- Numerical indexing
- Line indentation
- Bullet points

### Technique 5: Slide Design for Pyramid (Ch11)

**One idea per slide**:
- Title states the claim (not just topic)
- Visual supports title
- Text minimal (≤ 12 words per bullet)
- Slide sequence = pyramid top-down

**Slide progression**:
```
Slide 1: Thesis (recommendation)
Slides 2-N: Supporting reasons (1 per slide)
Slides N+1+: Evidence for each reason
Conclusion: Restate thesis + next steps
```

### Technique 6: Transitions Between Ideas (Ch10)

**Four transition techniques**:
1. **Narrative bridge**: Use S-C-Q format to introduce next point
2. **Connective flow**: Repeat key word from previous section
3. **Part summary**: Summarize before moving to new section
4. **Conclusion + transition**: End with thesis, bridge to next

**Example**:
- Section A ends: "...so we need three structural reforms"
- Section B begins: "These three reforms must address..."

## Problem-Solving Patterns

### Pattern 5: The Five-Question Sequential Analysis (Ch8)

**The complete problem-solving sequence**:
1. **Is there/could there be a problem?** → Defines problem existence
2. **Where is the problem?** → Locates problem specifically
3. **Why does it exist?** → Finds root causes (use diagnostic framework)
4. **What can we do?** → Generates solutions (use logic tree)
5. **What should we do?** → Selects optimal solution

**Use when**: Approaching any complex business problem systematically

### Pattern 5B: Structured Problem Definition (Ch8)

**The 3-Part Framework**:
1. **What is the problem?** (R1 vs. R2 gap)
2. **Why does it exist?** (Impact and root causes)
3. **What's the scope?** (What's in/out of scope)

**Formula**:
```
Current (R1): [What IS]
Desired (R2): [What SHOULD BE]
Gap: [Difference and why it matters]
Scope: [What we will/won't address]
```

### Pattern 6: Diagnostic vs. Evaluative Analysis

**Diagnostic** (root cause):
- "Why is X happening?"
- Use logic tree to explore causes
- Test hypotheses systematically

**Evaluative** (option selection):
- "Which option should we choose?"
- Compare options against criteria
- Use decision matrix

### Pattern 7: The Top-Down vs. Bottom-Up Thinking

**Top-Down Method** (start with conclusion):
1. State the conclusion you think is right
2. List what must be true to support it
3. Verify each support point with evidence

**Bottom-Up Method** (start with data):
1. Collect relevant facts and observations
2. Group into logical categories
3. Summarize each group into supporting idea
4. Combine into main point

## Presentation Patterns

### Pattern 8: One Idea Per Slide Rule

**How to apply**:
- Each slide = one supporting idea
- Visuals support the idea, not replace it
- Avoid text-heavy slides

**Structure**:
```
Title: [Main idea for this slide]
Visual: [Chart, image, or diagram]
Caption: [One sentence explaining visual]
Note: [Speaker notes go in notes pane, not on slide]
```

### Pattern 9: The Headline Method

**Principle**: Make each title a complete thought, not a topic

**Instead of**:
- "Market Trends"
- "Competitor Analysis"
- "Recommendation"

**Use**:
- "Market is consolidating around 3 major platforms"
- "Competitors lack our integration capability"
- "We should accelerate platform expansion"

## Template Patterns

### Pattern 10: Executive Summary Template

```
[SITUATION] [Company/Context]
[COMPLICATION] [New development]
[QUESTION] [Issue it creates]

[ANSWER] [Your main recommendation]

SUPPORTING REASONS:
- [Reason 1: Why recommendation is right]
- [Reason 2: Why it's urgent/important]
- [Reason 3: Why it's feasible]

NEXT STEPS:
1. [Action 1]
2. [Action 2]
3. [Action 3]
```

### Pattern 11: Proposal Structure Template

```
Executive Summary (SCQA format)
├─ Business Opportunity
├─ Proposed Solution
├─ Benefits (pyramid: 3 reasons)
└─ Investment Required

Detailed Analysis
├─ Market Analysis
├─ Technical Approach
├─ Risk Assessment
└─ Implementation Plan

Appendices
├─ Supporting Data
├─ Assumptions
└─ References
```

---

**Key Practice**: Pick one pattern (usually SCQA + Pyramid) and apply to your next communication. Make it automatic.
