# Chapter 8: Defining Problems Systematically

## Core Idea

Problems exist as gaps between current reality (R1) and desired reality (R2). Rigorous problem definition using the Situation-Complication-Question framework enables structured analysis and solution-finding.

## Frameworks Introduced

### 1. **Problem Definition Matrix (R1-R2 Gap Analysis)**
- **Current State (R1)**: Undesired result created by specific background and complication
- **Desired State (R2)**: Target result you want to achieve
- **Gap**: The problem to solve
- **When to use**: Before any analysis or solution proposal
- **How**: Visualize problem as continuous flow R1 → Problem → Solution → R2

### 2. **The Five-Question Sequential Analysis (连续分析)**
A logical sequence for problem-solving:
1. **Is there/could there be a problem (or opportunity)?**
2. **Where is the problem located?**
3. **Why does the problem exist (root causes)?**
4. **What can we do about it (possible solutions)?**
5. **What should we do (optimal solution)?**

**Decision points:**
- Questions 1-2 define the problem (for preamble)
- Question 3 seeks root causes (diagnostic framework)
- Questions 4-5 identify solutions (pyramid structure)

### 3. **Problem Definition Framework (四要素)**
The four essential elements that constitute any problem:
- **Context/Scene (切入点/序幕)**: Structure, process, industry state
- **Complication (困扰/困惑)**: Event or change that disrupts normal functioning
- **Current State (R1)**: Undesired result from the complication
- **Target State (R2)**: Desired outcome you wish to achieve

**Example:**
```
Scene: Company uses postal mail to sell industrial real estate
Complication: Market changed; response rates declining
Current State (R1): Sales growth down 10% (vs. +10% goal)
Target State (R2): Restore 10% growth rate
```

## Key Concepts

**Non-Desired Result (R1)**: The undesirable outcome currently occurring
- Could be performance decline
- Could be missed opportunity
- Often involves multiple factors

**Desired Result (R2)**: The target you want to achieve
- Must be specific (use numbers when possible)
- Examples: "Reduce churn from 8% to 2%", "Launch product in 6 months"
- Clear R2 enables better solution selection

**Complication Types**:
- External: Competitors, technology, regulation, market changes
- Internal: Process changes, system upgrades, market entry
- Recognized gaps: Performance lag, efficiency below average

## Mental Models

**Model 1: Problem as Flow**
```
Stable Background → Complication/Event → Undesired State (R1)
                      ↓
              Problem = Gap
                      ↓
         Solution bridges R1 to R2
```

**Model 2: Hierarchical Problem Levels**

Problems often operate at multiple levels:
- Level 1: Initial issue recognized (R1a → R2a)
- Level 2: Solution to Level 1 creates new issue (R1b → R2b)
- Level 3: Solution to Level 2 still doesn't resolve Level 1 (R1c → R2c)

**Use when**: Complex situations with interdependent problems

**Model 3: Reader Question Types**

Different readers need different answers based on their situation:
1. "What should we do?" (Don't know solution)
2. "Is this the right solution?" (Have solution, unsure)
3. "How do we implement it?" (Agree on solution, need steps)
4. "Why did it fail?" (Attempted solution didn't work)
5. "Which approach is best?" (Multiple options available)
6. "What strategy should we adopt?" (Unclear objectives)
7. "Do we have a problem?" (Benchmarking/comparison)

Reader's question type determines your pyramid structure.

## Worked Example

**Scenario**: Coffee shop chain declining sales

**Step 1: Define R1 and R2**
- R1 (Current): Same-store sales down 8% YoY
- R2 (Desired): Return to 3% YoY growth

**Step 2: Identify Background**
- 15 locations in metro area
- Established 5 years, previously stable 3-4% growth
- Premium positioning, specialty beans

**Step 3: Find Complication**
- Three new competitor chains opened in past year
- Customers shifting to cheaper alternatives
- Social media showing negative reviews about pricing

**Step 4: Map Problem Elements**
```
Background: Premium coffee shop chain, 15 locations
Complication: Three competitors launched; market shifting to value
R1: Sales down 8% (vs. expected +3% growth)
R2: Achieve +3% growth while maintaining premium position
```

**Step 5: Formulate Preamble**
"Our premium coffee chain has grown steadily for five years with 3-4% annual growth. However, three budget competitors opened near our locations last year, and customers have shifted toward cheaper options. As a result, our same-store sales are down 8% instead of the 3% growth we planned. **The question is: How can we restore growth while protecting our premium brand position?**"

## Converting Problem Definition to Pyramid Structure

Once problem is defined, the pyramid structure answers:
- **Top (Thesis)**: Your answer to the reader's question (What you should do)
- **Middle (Supporting Points)**: Reasons why this solution works
- **Bottom (Evidence)**: Data, analysis, examples supporting each reason

## Key Takeaways

1. **Define before solving** — Always establish R1 and R2 before proposing solutions
2. **Use four elements** — Every problem has scene, complication, R1, and R2
3. **Identify reader's question** — Different situations require different pyramid types
4. **Make R2 specific** — Vague goals produce vague solutions; use numbers and concrete results
5. **Multi-level problems require multi-level solutions** — Sometimes solving one level reveals deeper issues
6. **Preamble clarity enables pyramid clarity** — Clear problem definition makes pyramid structure obvious
